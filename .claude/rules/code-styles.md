## Рекомендации по языку C# и стилю 

### **Современный синтаксис**
  - Предпочтительны конструкторы с фиксированной областью видимости
  - пространства имен в пределах файла и глобальные операторы using.
  - file-scoped namespaces

### **Безопасность нулевых значений**
- Разрешены ссылочные типы, допускающие значение null (`<Nullable>enable</Nullable>`). 
- Не используй `!` для подавления предупреждений, если это не задокументировано.

### **Неизменяемость**
- Используй типы `record` или `readonly record struct` для Data Transfer Object (DTO), запросов API, ответов и событий домена.

### **Стиль написания кода**
- Используй `var` для локальных переменных, когда тип очевиден из правой части выражения.
- Применяй `nameof()` вместо строковых литералов для именования методов, свойств и событий.
- Применяй `is` и `as` вместо приведения типов.
- Свойства типа `bool` должны иметь в названии префикс `Is` или `Has` (например `IsUndelivered`, `HasChanges`).
- Используй `switch` выражения вместо `switch` операторов, когда это возможно.
- Используй `switch` выражения вместо цепочек `if-else`, когда это возможно.
- Устойчивая обработка ошибок: используй `try-catch` только для ожидаемых ошибок, а не для управления потоком выполнения.
- Объявляй методы и свойства как `private` по умолчанию, если они не предназначены для использования вне класса.
- Явно указывай модификаторы доступа для всех членов класса, чтобы избежать неявной видимости.
- Момечай классы как "sealed" по умолчанию, если они не предназначены для наследования."
- Создавай unit-тесты для всех публичных методов и свойств, чтобы обеспечить их корректную работу и предотвратить регрессии.
- Помещай private readonly поля в начало класса, чтобы улучшить читаемость и структуру кода перед публичными методами и свойствами.
- Помещай конструкторы после private readonly полей, чтобы улучшить читаемость и структуру кода перед публичными методами и свойствами.
- Помешай приватные (вспомогательные) методы после публичных методов и свойств, чтобы улучшить читаемость и структуру кода.
- Помещай override методы после публичных методов и свойств, после private методов, чтобы улучшить читаемость и структуру кода.
- Метод Dispose() и DisposeAsync() должны быть размещены в конце класса, после всех публичных и приватных методов, чтобы улучшить читаемость и структуру кода.

### **Асинхронный поток**
- Добавляй `Async` ко всем именам асинхронных методов
- Ппринудительно используйте `ConfigureAwait(false)` для библиотечной/основной логики, где это применимо.
- Всегда передавай `CancellationToken` в асинхронные методы.

### **Обработка ошибок**
- Используй подход Fail Fast.

### **Время/Часы**
- Всегда внедряй и используй `TimeProvider` вместо прямого вызова `DateTime.UtcNow`.
